# Security signals

This file is project-customizable: add, remove, or reword rows, change a risk level, or tune hints.
An edited copy is kept by `update --apply`.
`scripts/check_findings.py signals` reads the table below; editing a row changes `signals_loaded[]` on the next run without touching `SKILL.md`.

Every row loads on every security run, in any language or framework.
Hints never decide whether a row loads; they only point the agent at the changed files to read first.
For each row, the agent decides from the code whether the change has that behavior and writes one `coverage` entry `{signal_id, decision: applies|skipped, reason}`.
The checker rejects a summary where any row lacks that entry.

Columns:

- `trigger`: always `always`. An older `tag:<name>` value is accepted and treated the same way.
- `path hints`: comma-separated globs on directory or file names (`*` stays inside one directory, `**` crosses directories, case-insensitive). They carry no extension lists, so they fit any stack.
- `content hints`: backticked literal tokens, matched case-insensitively against the changed lines of `signals --diff`. They are examples from many stacks, not a complete list. Prose files (`*.md`, `*.rst`, `*.txt`, `docs/`) never count.
- `risk`: `high`, `med`, or `low`.
- `validator`: `deterministic` (script or unique marker), `agent` (reasoned judgment), or `none` (static note only).
- `do not flag`: exclusions the static and runtime passes must honor.

Tests, fixtures, e2e directories, storybook, and i18n catalogs never count as hints (see `DEFAULT_PATH_EXCLUDES` in `check_findings.py`).
